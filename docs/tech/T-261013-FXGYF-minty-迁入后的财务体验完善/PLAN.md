# Minty 迁入后的财务体验完善

## 范围与边界

按顺序完善收入口径、导入核对、财务项目与历史浏览。仅修改 Nobis；Minty 通过只读一致性副本验证，不修改原库，不迁入正式 Nobis，不开启 CloudKit、不提交或安装正式应用。

## 方案

- 流水列表明确使用“流水收入”，报告继续汇总月度税后到账与普通收入；报告和流水按期间互相跳转。
- 导入按类型展示文件内数量、新增／已有数量、金额和未映射内容。资产快照逐份核对，不累计。错误禁止确认；支持筛选和继续展开完整预览，成功后可打开本次新增记录。
- 财务为主的项目将预算与费用前置；项目卡展示预算执行，空待办与空笔记收为创建入口。费用预览限制首屏数量，完整历史可进入查看。
- 流水按月份分组、分币种小计，提供年月快速选择与条件摘要；保留当前页面筛选，不改变可见范围和默认创建规则。

## 验证

财务口径、导入分类统计、去重及错误阻断、日期分组使用自动测试。家庭／个人 Minty 副本分别迁入隔离空间，与源副本数量和金额核对，再次导入应新增零条。共享 UI 验证 macOS 与 iOS 模拟器构建，并用隔离数据检查代表性宽窄屏、浅深色与大字号；未覆盖项单独记录。

## 22 项兼容补充

用户继续授权仅用副本解决上一轮阻断。源码确认 Minty 的 IncomeFormView 将 month=0 标为非月度，IncomeViewModel 将其收入计入所属年份；IncomeRepository.normalized 使用 Double 计算 max(preTax-postTax, 0)。副本零元记录是他人请客的历史支出，虽当前 Minty 表单要求正数，存储层保留该记录。

- 延续既有 IncomeMonth 编码，month=0 表示非月度；详情和编辑显示非月度，年报单列，月报／逐月曲线不分摊。
- 仅 Minty 导入税额允许恢复与整数分税前减税后关系一致、误差不超过 0.00000001 元的尾差；保留原值说明，其他真实超精度仍阻断。Nobis 正常输入不推断税额。
- 只记收支的零元支出保留名称、日期、分类和来源，无分摊／欠款；退款、收入和成员结算仍要求正数。备份使用同一金额校验规则。
- 用完整个人包验证 22 条补导、重复导入、原字段与年度／逐月金额、备份及重启；不改源包及原库。

## 财务图表补齐

用户授权全部补齐评审建议，仍只使用副本：月度图区分零元与缺失、隐藏未来日期，非月度年报差异就近核对；分类条形图与筛选明细；项目预算／实际及计划项比较；资产截至所选月末和今天、实际快照点与分项结构／双日期增减；年度收入和截至同月同日支出比较及记录覆盖提示。图表保持币种和范围，点选金额、可读列表和明细入口并存，收入与资产长列表折叠。

验证重点为缺失／零元／未来区分、两类收入覆盖、资产日期边界和重复快照排除、退款及负数图形、筛选跳转、实际副本、双平台和窄屏。

## 图表辅助功能补验

用户授权在 Minty 副本上继续深色与辅助功能检查并直接修复问题。覆盖财务图表的深色实画面、大字号／横竖屏、可访问数据与键盘替代路径；发现的读屏、布局、并列柱和滚动问题在本任务中修复。原始库、正式安装及云边界保持不变；具体证据与工具限制见验证状态。

## 基础流程优先级

按用户最新指示暂缓语音播报、盲文、大字号专项。基础流程先处理以下已确认缺口：

1. 数据可靠性：重复来源不能任意跳过；批量失败、过期修订和超额退款应整批拒绝，不产生部分写入。
2. 导入效率：隔离批次复用记录投影，保持原业务校验与单次原子落盘；没有新增的重导不写存储。缓存仅存在于短生命周期内存批次，正式存储查询仍即时读取。
3. 日常查找：账本按空白分词，关键词可分布在名称、备注、分类、账户、原记录人与消费归属中；冲突记录须有同一个版本满足全部条件。

本轮使用已有 Minty JSON 副本，在新的隔离目录验证导入、22 条补导、幂等、金额、历史与重启；不读取或写入原始 Minty 库，不安装正式应用。旧成员映射与恢复合并按下述流程推进，提醒设置保留在后续计划，云协作仍暂缓。

## 成员映射与资产核对

Minty 副本的收入与资产表没有成员字段，不能从账本名称或记录人推断财务持有人。采用三个独立流程：

- 财务归属确认：在同一存储范围内按记录类型、名称／期间和待确认状态选择记录，明确选择成员（资产可选共同持有），预览后保存为新修订。保留原金额、期间、来源指纹与历史；提交前复核修订和同日同币种持有人重复。
- 旧本地成员映射：在旧本地内容入口逐人选择目标家庭成员，核对负责人／付款人、分摊、财务持有人及完成者的记录数量，并导出带来源 head 标识的 JSON 核对方案。禁止缺失引用成员、无效目标和多人合并为一人；不匹配历史称呼，不改写作者或授予权限；映射后可进入恢复合并流程，预览并显式确认新增当前版本。
- 资产核对：显式选择旧整体与已确认持有范围的同日同币种快照；九项分别计算“所选分项合计 − 旧整体”。重复／冲突、日期或币种不一致均阻断；相等仅指所选金额，不证明范围完整，不自动拆分、归档或合并。

验证使用已有 Minty JSON 副本和新建隔离库。真实副本归属确认后再次导入新增零条；实际快照衍生的同日分项仅作为内存测试样本，不代表真实资产持有情况。专项辅助功能继续暂缓。

## 恢复合并

设置中的隔离恢复和旧成员映射共用恢复预览。源备份校验后显式映射成员，仅允许同类范围；私人拥有者也须确认对应。按来源键和稳定 ID 去重，分类同名和资产同日同币种同持有人碰撞进入核对。已有差异可明确保留目标；删除、冲突、不唯一及缺失关联阻断整批。新记录关联重映射后在隔离内存库校验，一次保存；提交检查身份、权限和预览快照。当前版本新增到目标，完整源修订保存在来源备份，原范围不自动归档。所有验证使用新建本地副本，正式库不执行。
