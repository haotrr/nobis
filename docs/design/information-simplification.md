# 信息展示精简审查

2026-10-13。以下保留审查依据和建议；第一轮实施范围及验证见文末。

## 结论

冗余主要来自三处：页面和卡片层层解释用途；通用记录行不区分所在场景；默认状态、缺省字段与异常信息占用相同层级。应先减少重复语义，再调整留白与表面，避免通过缩小字号解决信息过载。

## 组件展示规则草案

| 场景 | 归属 | 状态 | 日期与类型 |
| --- | --- | --- | --- |
| 全部范围、搜索、今天混合内容 | 每项保留紧凑归属与明确私密标记 | 显示异常和会影响操作的状态 | 显示有助于识别的类型与日期；日程优先起止时间 |
| 已明确唯一归属的列表 | 相同归属可省略；筛选不能仅凭“共同”二字推定具体空间 | 常态省略，草稿／冲突／暂停／作废等保留 | 同类列表可省类型图标 |
| 项目内部 | 与父级空间一致时省略；不一致或归属不可用时显式显示 | 任务勾选表达完成状态，冲突单独显示 | 保留截止时间；来源笔记仍显示 |
| 指定日期的日历 | 按范围规则展示 | 异常状态保留 | 当天日期不用逐行重述；跨天日期、具体时间与“预计续费”等含义保留 |
| 详情与编辑 | 完整可查；编辑时明确实际保存范围 | 解释影响保存或操作的状态 | 完整信息可查 |

实现宜集中为少量语义化展示上下文，避免调用点散落大量 `show…` 开关。身份组件负责完整／紧凑样式，页面负责判断哪些上下文已经明确；不改变任何权限判断或数据查询。

## 不应一起删掉的信息

- 私密标记、归属不可用、跨范围区别；浏览筛选不代表创建范围。
- 草稿、未保存、冲突、保存失败与缺失价格；正常保存反馈可短暂展示，异常不能仅藏在详情。
- 付款人、消费归属、资产持有人与可见范围的区别。
- 币种、预计与实际、合计未包含的记录、资产快照截止日期。
- 笔记清单来源、当前筛选与清除入口、可访问性名称；不能仅用颜色承载状态。

## 实施与验收顺序

1. 先处理 `LifePage`、项目卡与默认状态，减少最确定的重复。
2. 给记录行、清单行及归属组件补充上下文；逐一核对今天、搜索、项目、安排和账本调用点。
3. 收敛今天的文字层级、详情卡片及报告说明；保留功能入口的可发现性。
4. 对比相同数据下的宽／窄窗口、小屏、大字号与浅深色；检查混合范围、私密项目、跨天日程、草稿、冲突、无日期和多币种。
5. 修改共享 UI 后完成双平台构建；布局涉及编辑器时补查键盘与中文组词。仅按实际覆盖记录结果，不推定真机或完整无障碍通过。
