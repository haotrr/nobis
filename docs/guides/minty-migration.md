# Minty 数据迁入

支持支出 CSV 和 Minty 迁移包的预览、校验及幂等导入；正式账本迁入仍需核对。

## 使用入口

在**设置 → 账务与导入 → 导入账单**选择 CSV 或迁移包，检查目标可见范围、映射、数量、金额及错误，再确认导入。核对区按业务类型分别展示文件内数量、新增／已有数量及金额；项目内计划项单列数量。资产逐份预览日期和净资产，不累计快照。可按类型和名称筛选预览，并继续展开超过 100 条的内容。导入完成后可打开本次新增记录及其详情。分类管理位于同一分组，改名不回写已有账单。

## CSV

接受 UTF-8（含 BOM）与 GBK 编码的支付宝／微信支出 CSV。搜索表头，不依赖固定行号；支持逗号、引号和多行备注。只导入支出；其他收支方向列入跳过数量，退款或关闭等非成功交易状态要求人工核对。不支持微信 XLSX。

通用／Minty 支出 CSV 的必需列：

```csv
date,item,amount,category
2026-10-01,车票,12.34,交通
```

可选列：`currency`（缺省 CNY）、`remark`、`uuid`、`recorded_by`、`attribution_kind`（family / personal / unassigned）、`attribution_member`。个人消费须填写称呼。日期须有效；超出币种精度的金额报错，不自动舍入。文件中有错误时整批不写入。

有来源交易 ID 时按来源与 ID 去重；无 ID 时按内容与相同内容出现次数去重。因此**无 ID CSV 的重叠导出、修改后重导需要人工核对**，不要当作可靠的双向同步。来源 ID 相同而内容变化时停止导入；已在 Nobis 调整的分类／项目不会被重导覆盖。

Nobis 导出的 CSV 包含记录 ID、来源、币种、状态、消费归属及项目 ID，适合核对和分析。它不是完整备份；导入器拒绝把该明细格式重新作为普通支出导入，以免丢失付款人与分摊。完整备份使用 JSON。

## Minty 完整关系迁移包

普通 CSV 缺少完整项目、计划项、订阅关系。仓库提供只读转换工具：

```sh
python3 scripts/export_minty.py /绝对路径/Minty账本副本.db /绝对路径/family-migration.json --ledger family
```

- 输入必须是完整、一致的 **SQLite 明文副本**；请通过 Minty／SQLite 备份机制取得，不要在运行中只复制主文件而漏掉 WAL。
- 若源库使用 SQLCipher 加密，该工具会明确失败。它不读取 Keychain、不尝试猜密钥。输入必须是已解密数据库副本；工具不提供解密功能。
- `--ledger` 是稳定的来源账本标识，重复导出同一账本须保持一致；不同账本必须使用不同标识。
- 工具只读输入、拒绝覆盖已有输出，保留支出、收入、资产快照、项目、计划项、订阅、配置各表内容。
- 在 Nobis 设置选择输出 JSON，检查目的空间、数量、金额、分类映射和错误，再确认导入。单文件上限 20 MB。

导入映射：

| Minty 内容 | Nobis 行为 |
| --- | --- |
| 支出 | 已确认、只记收支；保留原记录人／归属，付款人未知，不均摊 |
| 项目、父子项目 | 保留关联；进行中为 active，其他源状态为 completed |
| 预算、计划项 | 金额转整数分；关联支出保持引用；同笔账单关联父子项目时总额去重 |
| 订阅 | 独立订阅 + 历史支出引用；初始暂停，核对日期与付款人后启用，不自动补记历史扣款 |
| 支出分类配置 | 迁入分类记录，与已使用分类合并；其他配置留在源包 |
| 原 ID、UUID、创建时间 | 记录来源元数据；目标 ID 按来源与目标空间稳定映射 |
| 已删除源记录 | 不进入有效业务记录，留在源文件 |
| 收入记录 | year/month/income_type、税前／税后／可空税额，CNY；month=0 保留为非月度，仅计年报；重导补入不重复原支出 |
| 资产负债 | 九项完整快照，CNY；缺项、非法日期或超精度金额拒绝整批写入 |
| 其余配置 | 留在源包，尚未全部映射 |

确认导入前自动保存当前空间 JSON 备份和原始文件到 `Nobis/Migration/<批次UUID>/`。这些是确认产生的显式备份，退出云端家庭后仍保留，应按私人财务文件保管。原 Minty 数据库不修改。全部待写入记录先在内存中校验，业务修订与审计同一次 Store save；失败不写入部分账单。再次导入同来源不会重复入账。

导入不会自动修复不一致源数据、自动合并同名项目，也没有将旧昵称绑定真实共享成员。来源发生变更、断裂项目关系或金额无法精确转换时，先修正或核对源数据。

## 版本与验收边界

备份与共享格式统一见[架构](../architecture.md)；迁移包仍为 minty-nobis v1。

- 个人空间仍为本地库；家庭 CloudKit 同步仍待开发账号与两 Apple ID 真机验证。
- 已用真实账本副本完成隔离验收，结果见[验证状态](../verification.md)；没有迁入正式库。大量数据性能、生产同步、真机交互尚待后续验收。
- Minty 非月度收入（月份为 0）保留所属年份，不虚构日期、不分摊月份。年报单列非月度税后到账，月报与月度曲线不包含。
- Minty 原税额由 Double 税前减税后计算。仅当超精度税额与整数分计算的 max(税前−税后, 0) 相差不超过 0.00000001 元时恢复到分；预览警告及记录备注保留原值。其他超精度仍整批阻断；不修改源文件，不重算已有合法税额。
- 零元历史支出按只记收支保留，不产生付款、分摊或成员欠款；负数金额仍拒绝。

收入、资产与订阅成本的统计规则见[财务报告](../features/financial-reports.md)，待完成工作见[后续计划](../roadmap.md)。
