# Nobis 技术演进方案

本页定义未完成能力的设计条件，不重复当前源码架构。现有模块、存储和兼容格式见[架构](architecture.md)，产品目标见[产品方向](proposal.md)。

## 当前起点

- SwiftUI 双平台应用、Swift Package 分层及 Core Data 本地存储已经实现。
- CloudKit 主应用包含身份、邀请、共享与失权处理代码；真实双账号端到端验收未完成。
- CLI 仅查询显式导出的文件，不提供在线授权服务、数据库直连或写入。
- 现有记录类型覆盖项目、任务、订阅、日程、交易、分类、月收入、资产快照、笔记和评注；没有 Decision、Memory、Approval 业务模型。

## 共享与数据演进

| 能力 | 实施条件 |
| --- | --- |
| 双人共享放行 | 证明邀请身份正确、私密图不外泄、离线恢复收敛、并发修订不丢失、删除与撤权正确处理 |
| 私密跨设备同步 | 独立验证个人数据路径，不把本地私密库并入家庭共享根 |
| 旧家庭迁入 | 显式映射占位成员与真实身份，预览记录和财务归属，保留可恢复回执 |
| 拥有者交接 | 设计导出、新建家庭、邀请及核验流程，不能承诺原地转移 CKShare 所有权 |
| 附件 | 先定义存储、配额、授权、离线和删除传播；当前 HTTPS 图片不等于附件同步 |
| 格式升级 | 明确客户端兼容范围，未知类型不能被旧客户端静默覆盖，production schema 单独验收 |

金额与报表沿用[财务规则](features/financial-reports.md)，权限沿用[共同与私密](features/shared-life-design.md)。同步不能用最后写入覆盖替代修订冲突处理。

## 在线工具与 AI 写入（未实现）

1. 工具经同一业务入口访问；应用与 CLI/MCP 不并发直写 SQLite。XPC 或其他进程协调方案需验证生命周期与故障恢复。
2. 调用身份来自可信会话，限定成员、空间、动作和对象；不接受调用参数自行指定任意成员身份。
3. 写入先生成预览，包含目标、差异、权限范围和基础版本；批准绑定载荷摘要及版本，改参或版本变化后重新确认。
4. 批准须有有效期且一次消费；业务操作使用幂等键，重试不重复记账。有效期数值待实现时确定。
5. 权限、金额、版本和审计由确定性代码执行，提示词不能代替校验。
6. 工具输出区分本地提交与同步观察，返回来源及未知状态；不把导出完成解释为另一台设备已收到。

建议先开放授权范围内的只读查询，再评估低风险草稿写入。删除、敏感导出和外部发送需专门确认策略；不引入自动付款、转账或购票。向外部模型发送内容时执行数据最小化，不默认发送完整家庭库。

## 记忆与共同决策（未实现）

- 记忆保存来源、生成方式、确认状态和有效期；派生摘要不覆盖账单、日期等事实。
- 来源纠正、删除或撤权后，重新核验或移除派生内容；向量索引应可重建且遵循原权限。
- 决策保存议题、选项、成员意见、结论与复盘日期；双方确认同一版本才表示共同确认。
- 决策变更保留替代关系；产生任务或预算操作时显式关联，不静默改写财务事实。
- 不将自动人格画像、关系推断或敏感偏好推断纳入默认能力。

## 放行条件

共享、恢复、后台提醒、最低系统、无障碍和性能都需要实际证据。测试场景及 T01–T10 的当前结果仅维护在[验证状态](verification.md)，未完成工作仅维护在[后续计划](roadmap.md)。

万条数据性能、同步时延、第三方连接及跨设备附件没有已验收指标；不要将设计目标写成产品保证。
