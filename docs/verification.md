## iOS 小屏中文输入专项

环境：Nobis Accessibility QA，iPhone SE 3，iOS 26.2，375×667 / 667×375 pt，最大辅助功能字号、系统简体拼音。

- 笔记正文：约 1,300 字、40 段，末尾连续换行和组词；检查浅／深色 × 横／竖屏。正文组词期间不发布临时拼音到正式文档，放弃草稿后结束编辑回调不重新写入草稿。
- 项目、安排、记账表单：长名称／地点、长备注、连续换行、候选栏、旋转后光标可见；测试输入取消，未保存测试记录。
- 大字号聚焦多行备注采用单行编辑视口、内部滚动；横屏紧凑顶部操作栏保留取消／保存。布局变化后重新定位焦点，避免键盘遮挡及同步滚动循环。
- 组词颜色：共用原生表单输入从组词前使用动态文字颜色，外观变化只刷新颜色属性与渲染，不调用 setMarkedText / unmarkText 或切换第一响应者来规避。
- 单行字段：浅色横屏输入 ceshi → 深色 → 竖屏 → 浅色 → 选择原候选“测试”；临时拼音颜色正确，候选保留。
- 多行字段：20 段中文和换行，末尾输入 nihao；四种外观／方向组合均保留原文与候选。切换后继续 ma、选择“你好吗”，完整文本核对一致。
- 长文本由辅助功能赋值准备，拼音和选字使用实际软件键盘。颜色切换以添加安排的共用单／多行组件验证，不宣称逐一重测所有弹窗。

未覆盖第三方键盘、全部设备、完整 VoiceOver 或量化色彩对比度审计。页面验证发生在入口拆分之前，后续目录／入口整理仅完成构建与自动测试，未重跑全部交互。

## 已解决的本地文件保护故障

2026-10-12：元数据 JSON 的 POSIX 权限正常，但 CompleteUnlessOpen 保护等级下出现 EPERM；独立新文件复现。用户锁屏并解锁后恢复可读，确认与系统文件保护状态相关，未证明更底层密钥状态的原因。

LocalMetadataFile 在 macOS 使用 CompleteUntilFirstUserAuthentication 原子写入，iOS 保持 CompleteUnlessOpen；旧文件可读后迁移保护属性，不修改字节。不可读时保留原文件并报错，不重建身份或空间。

恢复后完整备份与原库的 JSON、修订、审计及空间 payload 校验一致；修复版冷启动通过，项目／安排／记账弹窗验证并取消测试输入。未清空既有数据。机器专属备份路径和临时日志不作为仓库依赖。
